# Task: reject an out-of-range `--port` with a usage error instead of a traceback

**Edit `scripts/status_page.py` and `tests/test_status_page.py`. Nothing else.**

This is a single, bounded fix. Do not refactor, do not improve anything the task does not name, and do not address any other review finding.

## Current behavior

`scripts/status_page.py:320`:

```python
    sv.add_argument("--port", type=int, default=DEFAULT_PORT, help="port to listen on")
```

accepts any integer; `scripts/status_page.py:285` then calls `ThreadingHTTPServer((host, port), handler)` and `socket.bind()` raises `OverflowError: bind(): port must be 0-65535`, which escapes `main()` as a traceback.

Repro:

```
python scripts/status_page.py serve --port -1
```

prints a traceback ending in `OverflowError: bind(): port must be 0-65535`. Same for `--port 70000`.

## Desired behavior

`--port` outside `0..65535` makes `serve` exit **non-zero** (argparse's 2) with a one-line stderr error naming `--port`, and no traceback. In-range values behave exactly as today. Implement as an argparse `type=` callable (e.g. `_port_number(text: str) -> int` that raises `argparse.ArgumentTypeError("port must be 0-65535")`) so the error happens before any socket is opened.
