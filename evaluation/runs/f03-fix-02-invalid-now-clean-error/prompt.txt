# Task: reject an unparseable `--now` with a usage error instead of a traceback

**Edit `scripts/status_page.py` and `tests/test_status_page.py`. Nothing else.**

This is a single, bounded fix. Do not refactor, do not improve anything the task does not name, and do not address any other review finding.

## Current behavior

`scripts/status_page.py:175`:

```python
    now = datetime.fromisoformat(args.now) if args.now else None
```

`--now` is declared at `scripts/status_page.py:308` as `st.add_argument("--now", help=...)` with no `type=`, so the string reaches `fromisoformat` unchecked and a bad value raises `ValueError: Invalid isoformat string: 'not-a-date'` which propagates out of `main()` as a traceback.

Repro:

```
python scripts/status_page.py status --runs C:/tmp --now not-a-date
```

prints a Python traceback ending in `ValueError: Invalid isoformat string: 'not-a-date'`.

## Desired behavior

An unparseable `--now` makes the `status` sub-command exit with a **non-zero** code (argparse's usual 2), print a one-line error on stderr that names the flag (`--now`), and print **no** traceback (`"Traceback"` must not appear in stderr). A valid `--now` keeps working exactly as before, and omitting `--now` keeps using the real UTC clock.

Simplest route: give the argument `type=datetime.fromisoformat` (argparse turns the ValueError into `error: argument --now: invalid fromisoformat value: 'not-a-date'` and exits 2), then use the already-parsed datetime in `_cmd_status`. A small `_parse_iso` helper raising `argparse.ArgumentTypeError` is equally acceptable.
