# Task: make the history sort robust to non-string run_id values

## Current behavior

`scripts/wayfinder_autopilot.py:901`: `entries.sort(key=lambda e: e["run_id"], reverse=True)`. `run_id` comes straight from the JSON (`:885`), so `{"run_id": 123, "state": "completed"}` yields an int, while unreadable entries (`:851`) and normal entries use strings. Python cannot order int against str, so `list_runs` raises `TypeError: '<' not supported between instances of 'int' and 'str'`, uncaught by `main()` (`:934`), exit 1.

Repro: `<ws>/logs/runs/20260816T120000-000000/run.json` = `{"run_id": 123, "state": "completed"}` and `<ws>/logs/runs/20260817T120000-000000/run.json` = `NOT JSON`; run `python scripts/wayfinder_autopilot.py --workspace <ws> history`.

## Desired behavior
