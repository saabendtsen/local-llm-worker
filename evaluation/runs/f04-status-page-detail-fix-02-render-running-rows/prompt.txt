# Task: show running runs as rows in their pipeline's table

**Edit `scripts/status_page.py` and `tests/test_status_page.py`. Nothing else.**

This is a single, bounded fix. Do not refactor, do not improve anything the task does not name, and do not address any other review finding.

## Current behavior

In `_serve_html`, each group's header is built from the group counts (`scripts/status_page.py:619`), which include in-flight runs, but the row loop is `for run in result["recent"]` (`scripts/status_page.py:623`) and `recent` holds finished runs only (they are the only records appended to it, `scripts/status_page.py:401`). So a page with one running and two finished `f03` runs prints the header `Pipeline: f03 (1 running, 2 finished)` above a table with two rows, both finished. The `state = "running"` branch at `scripts/status_page.py:632-635` can never fire.

## Desired behavior

Each group's table lists that group's **running** runs as well as its finished ones, newest first by `started_at`, with running rows above finished ones. A running row shows the same columns as a finished one: ID, kind, title, `state` = `running`, started, duration (from its live `duration_seconds`), and an empty detail cell (a running record has no `detail`). The header counts and the table rows agree on how many running runs there are.

The JSON is unchanged — this is a rendering fix only. Finished rows may stay limited to what `recent` holds; do not widen that.
