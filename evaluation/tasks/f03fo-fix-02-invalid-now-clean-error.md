# Task: reject an unparseable --now with a one-line error instead of a traceback

**Edit `scripts/status_page.py` and `tests/test_status_page.py`. Nothing else.**

This is a single, bounded fix. Do not refactor, do not improve anything the task does not name, and do not address any other review finding.

## Current behavior

scripts/status_page.py:175 parses the flag with `datetime.fromisoformat(args.now)` unguarded. `python scripts/status_page.py status --runs <any> --now not-a-date` prints a Python traceback ending in `ValueError: Invalid isoformat string: 'not-a-date'` and exits 1.

## Desired behavior

An unparseable `--now` value makes the `status` sub-command exit with a non-zero code, print a single-line error message to stderr that mentions `--now`, and print no traceback. A valid `--now` (e.g. `2026-08-19T10:02:00+00:00`) keeps working exactly as today: the clock is pinned and exit code is 0. Omitting `--now` keeps using `datetime.now(timezone.utc)`.

## Out of scope

- Do not change `collect_status` or the HTTP handler.
- Do not add validation for --port or --host.
- Do not address any other review finding.
