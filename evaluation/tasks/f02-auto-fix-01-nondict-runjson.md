# Task: treat a run.json that is valid JSON but not an object as an unreadable run

**Edit `scripts/wayfinder_autopilot.py` and `tests/test_wayfinder_autopilot.py`. Nothing else.**

This is a single, bounded fix. Do not refactor, do not improve anything the task does not name, and do not address any other review finding.

## Current behavior

In `list_runs` (`scripts/wayfinder_autopilot.py:847-865`) the file is parsed with `json.loads` and the result is used as a dict at `:865` (`started = metadata.get("started_at")`). The `except (json.JSONDecodeError, OSError)` at `:849` only handles parse/IO failures. If `run.json` contains `[1, 2, 3]`, `"x"`, `42`, `true` or `null`, `metadata.get` raises `AttributeError`, which `main()` (`:934`) does not catch either.

Repro: create `<ws>/logs/runs/20260816T120000-000000/run.json` containing `[1, 2, 3]` and run `python scripts/wayfinder_autopilot.py --workspace <ws> history` — traceback `AttributeError: 'list' object has no attribute 'get'`, exit 1.

## Desired behavior

A `run.json` whose parsed value is not a `dict` is reported exactly like a truncated one: an entry with `state: "unreadable"`, `run_id` = the directory name, `metadata` = the run.json path, all other fields `None`, and an `error` string (use `"run.json is not a JSON object"`). The process prints JSON and exits 0. Other runs in the same `runs/` tree are still listed normally.

Implement the check right after `json.loads` (e.g. `if not isinstance(metadata, dict): ... continue`). Factor the unreadable-entry dict into a private helper (e.g. `_unreadable_entry(child, metadata_path, error)`) so both the parse-failure path and the non-dict path build the same shape.

## Out of scope

- Do not change the shape or values of entries for valid run.json files.
- Do not change `run_once`, `build_parser`, or `main()`.
- Do not change the existing truncated-JSON tests' assertions (`test_list_runs_handles_truncated_run_json`, `test_cli_history_truncated_run_json`).
- Do not address any other review finding.
